#### 🚨 Root Cause 2: Android Play Integrity & App Signing Key Fingerprints
* **How native Android Phone Auth works**: `@react-native-firebase/auth` on Android uses the **Google Play Integrity API** (or SMS Retriever) to verify the app integrity before Google dispatches an OTP SMS without CAPTCHA.
* **Live Hashes on Firebase**:
  * SHA-1: 5 hashes registered.
  * SHA-256: 4 hashes registered.
* **Why some Android devices fail**:
  1. **Google Play App Signing**: If you installed the app via Google Play Store (Production, Internal Testing Track, or Closed Testing), Google re-signs the APK with the **Google Play App Signing key**. If the Google Play App Signing SHA-256 certificate fingerprint is not added to Firebase Console, Play Integrity fails.
  2. **EAS Build Keystores**: If new EAS build profiles were created with a new Android keystore, their SHA-1 / SHA-256 will mismatch what is in Firebase.
  3. **Non-GMS / Rooted / Emulator Devices**: Devices without Google Play Services (e.g. Huawei, custom ROMs, rooted devices, certain emulators) fail Play Integrity verification. Native Firebase Auth will attempt a fallback that fails and throws `auth/app-not-authorized` or `auth/captcha-check-failed`.

#### 🚨 Root Cause 3: iOS Silent APNs Verification & Safari Web Fallback
* **How native iOS Phone Auth works**: `@react-native-firebase/auth` uses **silent APNs push notifications** to verify the device seamlessly.
* **Why some iOS devices fail**:
  1. If an **APNs Authentication Key (`.p8`)** is not uploaded in Firebase Console under *Project Settings > Cloud Messaging / Apple app*, or if push notifications are disabled/unsupported on the test device (e.g., iOS Simulator), Firebase falls back to opening a hidden Safari / web reCAPTCHA modal.
  2. If the user cancels the web reCAPTCHA, closes the browser, or if the reCAPTCHA token is blocked, Firebase throws `auth/captcha-check-failed` or `auth/cancelled-popup-request`.
